# Heltec V4 Web Monitor v1.4.0

Первый релиз в репозитории [enotikov/heltec-v4-web-monitor](https://github.com/enotikov/heltec-v4-web-monitor) основан на MeshCore `v1.16.0` и MeshCoreTel-firmware. Он расширяет локальную веб-панель ретранслятора монитором пакетов, картой узлов, настройкой координат и аппаратно ограниченной мощностью высокомощной Heltec V4/V4.3.

Тег релиза:

```text
repeater-mqtt-meshcoretel-v1.4.0
```

Перед созданием тега переменная GitHub Actions `OFFICIAL_MESHCORE_VERSION` должна иметь значение:

```text
v1.16.0
```

## Главное

- новая страница `/packets` с живым журналом RX/TX/TX-failed;
- подробная карточка пакета по нажатию на строку;
- фильтры, режим Live и экспорт CSV;
- карта проверенных advert-узлов;
- трёхсекундная анимация движения пакетов;
- сохранение пользовательского масштаба и положения карты;
- до 128 найденных узлов в RAM до перезагрузки без вытеснения;
- выбор координат репитера точкой на карте;
- настройка выходной мощности высокомощной Heltec V4 в диапазоне `3…28 dBm`;
- атомарное изменение SSID и пароля Wi-Fi;
- новые API и CLI-команды для пакетов и мощности.

## Монитор пакетов

Кольцевой журнал хранит до 128 последних записей. Сохраняются только радиометаданные: направление, тип, маршрут, размеры, RSSI/SNR, число хопов, airtime, routing score, transport codes, сокращённый хеш и последовательный номер.

Зашифрованное содержимое payload не сохраняется и не отображается.

Подробную карточку можно открыть мышью, клавишами `Enter` или `Space`. Она закрывается крестиком, `Escape` или нажатием вне окна. JSON сохранённых метаданных можно скопировать.

## Карта узлов

Точки создаются только из advert, успешно прошедших штатную проверку MeshCore и содержащих координаты. Сплошные линии используются для проверенной связи, пунктир — для однозначного совпадения короткого path hash, которое остаётся предположением.

Реестр Heltec V4:

- вмещает до 128 проверенных узлов;
- не вытесняет ранее найденные узлы;
- сохраняет последние известные координаты при advert без координат;
- не очищается вместе с журналом пакетов;
- сбрасывается только при перезагрузке платы.

Карта подбирает обзор один раз. Последующие обновления не сбрасывают выбранные пользователем zoom и положение.

## Heltec V4 TX power

Для высокомощной Heltec WiFi LoRa 32 V4/V4.3 диапазона `863–928 МГц` поле веб-панели показывает оценочную выходную мощность платы:

- минимум: `3 dBm`;
- максимум: `28 dBm`;
- управление SX1262: `-9…16 dBm`;
- оценочное усиление PA: `12 dB`.

Прошивка ограничивает значение аппаратным максимумом платы, но не применяет региональный лимит или ограничение EIRP. Ответственность за местные требования остаётся на операторе.

Эта настройка не предназначена для низкомощной Heltec V4 или другой платы.

## Установка

GitHub Actions собирает для релиза только окружение `heltec_v4_repeater_mqtt` и прикладывает два образа: обычный `.bin` для OTA и `-merged.bin` для полной USB-прошивки. Перед публикацией нужно сверить SHA-256 файлов из draft release с хешами скачанных артефактов.

### OTA из `/app`

Для обновления существующей установки используйте обычный файл:

```text
heltec_v4_repeater_mqtt-<version>.bin
```

Откройте `Firmware Update`, выберите файл без `-merged`, нажмите `Upload` и дождитесь автоматической перезагрузки. Настройки сохраняются. После запуска обновите страницу без кеша.

### Чистая установка

Для полной записи через USB используйте:

```text
heltec_v4_repeater_mqtt-<version>-merged.bin
```

Полный образ записывается с адреса `0x0`. Его нельзя загружать через Firmware Update.

Рекомендуемый прошивальщик: <https://meshcoretel.ru/ru/flasher>.

## Новые CLI-команды

```text
get web.packets.status
clear web.packets
get web.tx
set web.tx <dBm>
set wifi.credentials <ssid><TAB><password>
```

## Новый API

```text
GET /api/packets?since=<sequence>&limit=<1..64>&include_nodes=1
```

API требует токен администратора в `X-Auth-Token`. При `include_nodes=1` ответ содержит координаты самого репитера и реестр проверенных advert-узлов. Полные публичные ключи и содержимое payload не выдаются.

## Совместимость и ограничения

- Основной новый интерфейс оптимизирован для высокомощной Heltec V4/V4.3 OLED с 2 Мб PSRAM.
- Leaflet и тайлы OpenStreetMap загружаются браузером из интернета; таблица пакетов работает без карты.
- Журнал пакетов и реестр узлов находятся в RAM и очищаются при перезагрузке.
- Короткий path hash не доказывает отправителя или получателя.
- Веб-панель использует самоподписанный локальный сертификат.
- Веб-интерфейс и API не следует публиковать напрямую в интернет.

## Первый импорт в новый репозиторий

Ветка `main` нового репозитория была создана отдельным начальным коммитом и не имеет общей Git-истории с MeshCoreTel-firmware. Перед первым pull request нужно один раз объединить истории с сохранением содержимого этой ветки либо, если владелец репозитория сознательно выбирает полный импорт, заменить исходный однострочный `main`. После первого импорта дальнейшие обновления выполняются обычными pull request.

Исходный репозиторий должен оставаться подключённым как remote `upstream`:

```text
origin   https://github.com/enotikov/heltec-v4-web-monitor.git
upstream https://github.com/VBart/MeshCoreTel-firmware.git
```
