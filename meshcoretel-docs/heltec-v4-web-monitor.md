# Heltec V4: веб-панель и монитор пакетов

Эта страница описывает расширенную сборку `heltec_v4_repeater_mqtt` на базе MeshCore `v1.16.0`, подготовленную для высокомощной Heltec WiFi LoRa 32 V4/V4.3 с OLED, ESP32-S3, 16 Мб flash, 2 Мб PSRAM, SX1262 и встроенным усилителем LoRa.

Сборка остаётся прошивкой **ретранслятора MeshCore**. Wi-Fi, MQTT, веб-интерфейс и монитор пакетов дополняют работу репитера и не превращают его в отдельный тип наблюдателя.

## Для какого оборудования предназначена сборка

Используйте её для:

- Heltec WiFi LoRa 32 V4 или V4.3 с OLED;
- высокомощной версии диапазона `863–928 МГц` с заявленным выходом LoRa до `28±1 dBm`;
- окружения PlatformIO `heltec_v4_repeater_mqtt`.

Не используйте этот образ для:

- Heltec V3;
- TFT-варианта Heltec V4;
- Wireless Tracker;
- низкомощной версии V4;
- платы с другой разметкой flash.

Перед передачей обязательно подключите исправную антенну нужного диапазона. Работа усилителя без антенны может повредить ВЧ-тракт.

## Что входит в прошивку

### Ретранслятор и MQTT

- штатная логика MeshCore repeater;
- подключение к Wi-Fi в режиме клиента;
- DHCP и синхронизация времени по NTP;
- передача телеметрии и пакетов в MeshCoreTel;
- опциональные брокеры LetsMesh EU и US;
- настройки публикации RX, TX, raw-пакетов и статуса;
- режим Ghost Node для сохранения Wi-Fi/MQTT без активной ретрансляции и advert-трафика.

### Локальная веб-панель

Панель работает по адресу:

```text
https://<IP-адрес-узла>/app
```

Она использует административный пароль репитера и самоподписанный HTTPS-сертификат. Первое предупреждение браузера для локального сертификата ожидаемо.

Основные страницы:

- `/app` — конфигурация репитера, Wi-Fi, радио, MQTT, CLI и обновление прошивки;
- `/stats` — текущее состояние, память, радио, сервисы, соседи, события и история;
- `/packets` — живой монитор метаданных принятых, переданных и неудачно переданных пакетов.

### Настройка координат на карте

Координаты ретранслятора можно:

- ввести вручную;
- выбрать нажатием на карту;
- изменить перетаскиванием маркера.

Кнопка `Save coordinates` последовательно сохраняет широту и долготу. Карта использует Leaflet и тайлы OpenStreetMap, поэтому браузеру нужен доступ в интернет. Само сохранение координат и остальные функции панели от карты не зависят.

### Мощность передатчика

Поле `Board output power (dBm)` задаёт оценочную мощность на выходе высокомощной платы, а не значение управления радиочипом.

Для этой сборки:

- диапазон интерфейса: `3…28 dBm`;
- внутреннее управление SX1262: `-9…16 dBm`;
- оценочное усиление встроенного PA: около `12 dB`;
- аппаратный верхний предел: `28 dBm`.

Региональный лимит мощности или EIRP прошивка не накладывает. Оператор самостоятельно отвечает за допустимую мощность, усиление антенны и соблюдение местных требований.

### Монитор пакетов

Страница `/packets` хранит до 128 последних записей в кольцевом буфере оперативной памяти. Для каждой записи доступны:

- локальное время или uptime;
- направление `RX`, `TX` или `TX failed`;
- тип payload и маршрут;
- RSSI и SNR для принятого пакета;
- полный размер, размер payload и служебный размер;
- число хопов и размер path hash;
- расчётное эфирное время;
- routing score и transport codes;
- сокращённый четырёхбайтовый хеш пакета;
- порядковый номер записи.

Нажатие на строку открывает подробную карточку. Её можно закрыть крестиком, нажатием вне окна или клавишей `Escape`. Кнопка `Copy metadata` копирует JSON только с сохранёнными метаданными.

Зашифрованное содержимое payload не сохраняется и не показывается.

### Узлы и анимация на карте

Узел добавляется в проверенный реестр только после корректно обработанного advert с подписью. На карте:

- зелёная линия означает RX от проверенного advert-узла;
- синяя линия означает TX к проверенной точке;
- пунктир показывает лишь однозначное совпадение сокращённого хеша пути;
- импульс возле репитера означает пакет, конечную точку которого определить нельзя.

Линия или импульс живут три секунды. Метки узлов остаются.

Карта автоматически выбирает обзор только при первом получении координат. После этого обновления пакетов и появление новых узлов не изменяют выбранные пользователем масштаб и положение.

Для Heltec V4 сохраняются до 128 уникальных проверенных узлов:

- старые узлы не вытесняются новыми;
- обновлённый advert меняет имя, тип, время и известные координаты;
- advert без координат не стирает ранее известную точку;
- `Clear` очищает журнал пакетов, но не реестр карты;
- реестр карты очищается только после перезагрузки платы;
- после заполнения 128 мест дополнительные неизвестные узлы не заменяют сохранённые.

Реестр находится в RAM и намеренно не записывается во flash, чтобы не изнашивать память частыми advert-сообщениями.

## Варианты установки

### Обновление через Firmware Update

Это рекомендуемый способ для уже работающего узла с доступной веб-панелью.

1. Скачайте обычный файл `heltec_v4_repeater_mqtt-...bin` без суффикса `-merged`.
2. Откройте `https://<IP-адрес-узла>/app` и войдите паролем администратора.
3. Найдите раздел `Firmware Update`.
4. Выберите обычный `.bin` и нажмите `Upload`.
5. Подтвердите обновление и дождитесь `100%`.
6. Не отключайте питание и Wi-Fi до автоматической перезагрузки.
7. Подождите около минуты и откройте панель заново.
8. Если браузер показывает старую разметку, выполните обновление без кеша (`Ctrl+F5`).

Через веб-интерфейс нельзя загружать `-merged.bin`: полный образ предназначен для записи с адреса `0x0` через USB.

OTA сохраняет настройки Wi-Fi, MQTT, ключи, имя, координаты и параметры радио. Оперативные журналы пакетов и найденных узлов после перезагрузки начинают заполняться заново.

### Чистая установка через USB

Для первой установки или восстановления используйте полный `-merged.bin` и веб-прошивальщик MeshCoreTel:

1. Подключите плату качественным USB-кабелем с передачей данных.
2. Откройте <https://meshcoretel.ru/ru/flasher> в браузере с Web Serial.
3. При необходимости переведите ESP32-S3 в загрузчик: удерживайте `PRG/BOOT`, коротко нажмите `RST`, затем отпустите `PRG/BOOT`.
4. Выберите правильную сборку Heltec V4 repeater MQTT.
5. Для чистой установки включите очистку устройства и используйте полный образ.
6. Дождитесь проверки записи.
7. Коротко нажмите `RST`, если плата не вышла из загрузчика автоматически.

Чистая установка со стиранием flash удаляет сохранённые настройки и ключи. Перед ней сохраните всё, что потребуется восстановить.

## Первая настройка

### 1. Wi-Fi

Через последовательную консоль задайте:

```text
set wifi.ssid <имя-сети>
set wifi.pwd <пароль>
get wifi.status
```

После первого входа в веб-панель SSID и пароль можно менять одной операцией. Панель использует атомарную команду `set wifi.credentials`, чтобы соединение не оборвалось между раздельным сохранением SSID и пароля.

### 2. Параметры репитера

В `/app` проверьте:

- `Device Name`;
- административный и гостевой пароли;
- приватный ключ;
- координаты;
- radio preset;
- мощность передатчика;
- path hash mode;
- advert interval, flood interval и flood max;
- owner info.

После изменения radio preset перезагрузите устройство, если панель сообщает о необходимости перезапуска.

### 3. MQTT

Задайте код локации и включите нужный брокер:

```text
set mqtt.iata <код>
set mqtt.meshcoretel on
get mqtt.status
```

При необходимости заполните MQTT Owner и Email, включите публикацию TX/raw и дополнительные LetsMesh endpoints. Одновременно разрешено не более двух брокеров.

### 4. Проверка веб-функций

```text
get web.status
get web.stats.status
get web.packets.status
get web.tx
memory
```

Затем откройте `/stats` и `/packets`.

## Ежедневное использование `/packets`

1. Откройте страницу `Packets` в верхней навигации.
2. Настройте фильтр направления, типа, минимального RSSI и числа строк.
3. При необходимости выключите `Live`, чтобы временно остановить опрос.
4. Нажмите на строку для просмотра подробностей.
5. Используйте `Export CSV` для выгрузки текущей отфильтрованной выборки.
6. Используйте `Clear` только для очистки записей пакетов — точки известных узлов останутся до перезагрузки.

Не трактуйте пунктирный путь как доказательство отправителя или получателя. Это лишь уникальное совпадение короткого path hash с узлом, который ранее прислал проверенный advert.

## Безопасность

- Не публикуйте веб-панель напрямую в интернет.
- Используйте уникальный административный пароль.
- Не передавайте токен `X-Auth-Token` сторонним сервисам.
- Самоподписанный сертификат защищает канал шифрованием, но браузер не может подтвердить принадлежность локального адреса без ручного доверия.
- Приватный ключ отображается только администратору; не размещайте его в отчётах, снимках экрана и issue.
- Экспорт пакетов содержит радиометаданные и может раскрывать топологию сети, даже несмотря на отсутствие payload.

## Ограничения

- Карты требуют интернет-доступа браузера к Leaflet и OpenStreetMap.
- Координаты узла известны только после advert, содержащего координаты.
- Для зашифрованного пакета прошивка обычно не может доказать отправителя или адресата.
- Журнал пакетов и реестр карты находятся в RAM и сбрасываются при перезагрузке.
- Кольцевой журнал содержит 128 последних пакетов; новые записи заменяют самые старые.
- Реестр карты содержит максимум 128 узлов и после заполнения не принимает дополнительные неизвестные точки до перезагрузки.
- Частый опрос API увеличивает нагрузку на устройство; встроенная страница прекращает опрос в фоновой вкладке.

## Диагностика

### Панель не открывается

Проверьте:

```text
get wifi.status
get web.status
```

Открывайте HTTPS-адрес напрямую. При первом подключении примите предупреждение о локальном сертификате.

### После OTA открывается старая страница

- подождите завершения перезагрузки;
- выполните `Ctrl+F5`;
- выйдите и войдите снова;
- проверьте версию в разделе `Info`.

### Карта пустая

- убедитесь, что браузер имеет доступ в интернет;
- проверьте координаты самого репитера;
- дождитесь проверенных advert с координатами;
- таблица пакетов должна работать даже при недоступной карте.

### Пакет не связан с узлом

Это нормальное поведение для зашифрованного трафика. Проверенная связь доступна для обработанного advert. Для остальных пакетов могут отображаться лишь однозначные совпадения узлов пути.

### Обновление не завершилось

- не загружайте `-merged.bin` через Firmware Update;
- повторите OTA по стабильному Wi-Fi;
- при недоступной панели восстановите устройство полным образом через USB;
- после USB-прошивки при необходимости коротко нажмите `RST`.

## Проверка после обновления

Минимальный контрольный список:

1. Узел подключился к прежней Wi-Fi-сети.
2. В `Info` отображается ожидаемая версия.
3. `get mqtt.status` показывает нужные endpoints.
4. Radio preset и мощность не изменились неожиданно.
5. Координаты репитера корректны.
6. `/stats` открывается.
7. `/packets` получает новые записи.
8. Нажатие на пакет открывает подробную карточку.
9. Ручное приближение карты сохраняется при новых пакетах.
10. Найденные точки остаются после `Clear` и исчезают только после перезагрузки.
